# Bug Severity and Priority

## 1. Severity

Severity describes the impact of a defect on application functionality.

| Severity | Description | Example |
|---|---|---|
| Blocker | Application cannot be used | Application does not start |
| Critical | Major functionality is unavailable | Users cannot complete orders |
| Major | Important functionality is broken | Products cannot be added to cart |
| Minor | Functionality works with minor issues | Incorrect validation message |
| Trivial | Cosmetic issue | Minor alignment problem |

## 2. Priority

Priority describes how urgently a defect should be fixed.

| Priority | Description |
|---|---|
| High | Requires immediate attention |
| Medium | Should be fixed in the normal development cycle |
| Low | Can be fixed later |

## 3. Difference Between Severity and Priority

Severity measures the impact of a defect.

Priority measures the urgency of fixing it.

A defect can have:
- High Severity / High Priority
- High Severity / Low Priority
- Low Severity / High Priority
- Low Severity / Low Priority

## 4. Examples

**Example 1:**
A checkout process is completely unavailable.

Severity: Critical

Priority: High

**Example 2:**
A company logo is slightly misaligned.

Severity: Trivial

Priority: Low

**Example 3:**
An incorrect promotional banner is displayed during a major marketing campaign.

Severity: Minor

Priority: High
